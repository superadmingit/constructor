# stamp_engine: деталь → развёртка, 3D, чертёж, расчёт штампов

Для программиста, который раньше не работал с листовой штамповкой. Решения и причины — в **ARCHITECTURE.md**.
Термины с картинками (шильдик, ползун, пуансон, матрица, радиус гиба) — на странице данных цеха, вкладка «Словарь».

## Что делает сейчас

Для **любой** плоской или гнутой детали (гибы по прямым линиям):
1. Строит развёртку по наружным размерам гнутой детали (DXF для NX, AutoCAD, станков).
2. Строит 3D (STEP для любого CAD).
3. Делает чертёж PDF: виды детали в одном масштабе, развёртка в масштабе, таблица координат отверстий, таблица гибов.
4. Считает технологию: проверки, операции, схемы (совмещённый / гильотина + обрубка / прогрессивный), усилия, прессы.

Чертежей самих штампов ещё нет: это этап 2.

## Веб-приложение для стороннего пользователя

Страница `/`: выбрать тип детали, ввести размеры по буквам (с подсказками «чем и как мерить»), отверстия, прессы.
Второй шаг: фото детали (общий вид, сверху, сбоку, с торца, чертёж или бирка, сомнительное место) с подсказкой, как снимать. Фото необязательны, сжимаются на телефоне и попадают в архив с результатом. Размеры по фото не определяются.
На выходе: картинка детали, развёртка, варианты штамповки с усилиями, файлы PDF, DXF, STEP, отчёт, модель JSON и архив с фото.
API для программ: `/api/docs`. Фото: `POST /api/session`, затем `POST /api/session/{id}/photo/{slot}` (тело запроса — JPEG или PNG до 6 МБ), потом `session` в `/api/calculate`. Файлы хранятся 3 часа; постоянное хранилище (Supabase Storage) — этап 1 в ARCHITECTURE.md.

```
pip install -r requirements.txt

```

### Как дать ссылку стороннему человеку (бесплатно, Hugging Face Spaces)

1. На huggingface.co: New Space → SDK **Docker** → имя, например `constructor` → Public.
2. Там же: Settings → Access Tokens → токен с правом **Write**.
3. Файлы автоматизации лежат в `ci-templates/`. Чтобы включить, перенесите их в `.github/workflows/` (на github.com: Add file → Create new file, имя `.github/workflows/deploy-hf.yml`, вставить содержимое). Затем Settings → Secrets and variables → Actions:
   секрет `HF_TOKEN` (токен из п. 2) и переменная `HF_SPACE` (например `superadmingit/constructor`).
4. Actions → deploy-to-huggingface → Run workflow. Дальше каждый push в main обновляет приложение сам.

Ссылка для людей: `https://huggingface.co/spaces/<пользователь>/<имя>`. Первая сборка идёт 5–10 минут.

## Главное правило

**Нет данных — не значит «нормально».** У каждого числа есть источник: измерено, со слов, допущение, нет данных.
Пока нормы не утверждены конструктором или развёртка не подтверждена пробой, все выходы помечены
«ЧЕРНОВИК — НЕ ДЛЯ ИЗГОТОВЛЕНИЯ». Это закреплено тестами, не ломайте.

## Как описать новую деталь

Быстро, для типовых деталей — шаблон и размеры по буквам (так будет вводить рабочий):

```python
from stamp_engine.sheet.families import build, measurement_plan
measurement_plan("channel")   # что мерить: A длина, B наружная ширина, C высота полок, S, R, U
spec = build("channel", {"A": 60, "B": 40, "C": 25, "S": 2, "R": None, "U": None},   # None = «не знаю»
             holes=[{"face": "base", "kind": "round", "d": 10.5, "x": 20, "y": 30}],
             meta={"id": "SK-002", "material": {"group": "soft_steel"}})
```

Полностью — JSON модели (пример `examples/skoba_u.json`, сложный пример `examples/gem0004.json`):
основание (контур в плане, наружные размеры), полки на прямых рёбрах (номер ребра, угол, вверх/вниз, габаритная высота
или профиль переменной высоты, участок ребра), подсечки (линия, высота, угол), отверстия (в основании — x, y;
в полке — s вдоль ребра и e от края полки). Соглашение о размерах — в начале `stamp_engine/sheet/unfold.py`.

## Правила работы с кодом

1. Коэффициент нужен в формуле — добавьте его в `norms/shop_norms.yaml` с `title`, `typical`, `why`. Чисел в коде не пишите.
2. Формула или геометрия без теста с ручным расчётом не принимается.
3. **Кода под конкретную деталь не бывает.** Новая деталь — это данные (JSON или шаблон), а не новый модуль.
4. Пуансон и матрица: при **пробивке** размер задаёт пуансон (по верхней границе отверстия, матрица больше на 2z);
   при **вырубке** размер задаёт матрица (по нижней границе детали, пуансон меньше на 2z).
5. Отверстие ближе 2·S к гибу пробивается **после** гиба. Планировщик это учитывает.
6. Модель ловит ошибки описания и объясняет их человеку (SheetError, NotSupported). Не глушите эти исключения.
